Ich habe meinen Apps und Experimenten ein gemeinsames Zuhause gegeben: **AppShelf**.

Dort findest du Screenshots, Browser-Demos und verfügbare Downloads. Hinter dem Katalog stecken strukturierte Projektpakete, ein statischer Build und GitHub Actions. Im Projektjournal zeige ich, wie daraus die öffentliche Seite wird und warum ich die Veröffentlichung so aufgebaut habe.

Falls du gern an eigenen Apps oder Hardware-Projekten tüftelst: Mich interessiert, wie du deine Projekte präsentierst und welche Infos dir beim Ausprobieren wichtig sind.

## Für einen technischen oder beruflichen Einblick

Mit **AppShelf** dokumentiere ich ein Projekt, das eine gemeinsame Oberfläche mit einem nachvollziehbaren Veröffentlichungsablauf verbindet.

Projektmanifeste liefern die Inhalte. Node.js erzeugt Katalog und Detailseiten. GitHub Actions prüft und veröffentlicht die statische Ausgabe auf GitHub Pages; App-Dateien liegen in GitHub Releases.

Die Projektvorstellung erklärt Architektur, technische Entscheidungen und eine konkrete Überarbeitung der Screenshot-Karten. Demo, Quellcode und verlinkte Workflows machen den beschriebenen Stand nachvollziehbar. Bei Entwicklung und Dokumentation nutze ich auch KI-Unterstützung.
